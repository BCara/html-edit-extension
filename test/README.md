# Tests

Three suites, all runnable without installing anything.

```
./test/run.sh            # all three; the ~1MB fixture is regenerated first
node test/node-test.js   # tokenizer, splice and write-back, no browser
```

| Suite | What it covers |
| --- | --- |
| `node-test.js` | tokenizer, splicing, escaping, write-back, wall-clock performance |
| `mapping-test.html` | the offset map against the real HTML parser, over every fixture |
| `editor-test.html` | edit mode end to end: typing, Enter, paste, undo, and the file that comes out |

`run.sh` drives headless Chrome with `--allow-file-access-from-files` so the
harness can fetch its fixtures and read the iframes it loads them into. That is
a **test-only** flag; the extension itself relies on the user's "Allow access to
file URLs" toggle.

To watch a browser suite instead of reading its output, open the page from a
`file://` URL in a Chrome window started with that same flag:

```
google-chrome --allow-file-access-from-files --user-data-dir=/tmp/qe-profile \
  file://$PWD/test/mapping-test.html \
  file://$PWD/test/editor-test.html
```

## What the browser suite does

Every fixture is loaded **twice**, deliberately:

- in an `<iframe>` from its real `file://` URL — the authoritative parse, same
  parser and same scripting-enabled state as the page the extension runs on.
  Used to check the map against reality.
- through `DOMParser`, once for the original source and once for the edited
  source. Two documents produced the same way can be compared element for
  element, which is what makes "edit everything and check nothing else moved"
  a meaningful test.

Applied to every fixture:

| Check | Claim |
| --- | --- |
| spans quote the source | `source.slice(start, end)` is exactly the recorded text |
| spans are ordered | ranges never overlap or run backwards |
| every node accounted for | each DOM text node maps to a span, or is positively identified as a parser-merged run |
| merged runs are inert | merged nodes are whitespace and never editable |
| coverage | every non-whitespace run of text outside code/metadata **is** editable |
| decode round-trip | each span, decoded as the parser decodes, equals the node's text |
| **no edits is byte-identical** | the headline guarantee |
| structure preserved | editing *all* text leaves tags, attributes, comments and doctype identical |
| text round-trip | the edited file parses back to exactly the text that was typed, and nothing else moved |

## Fixtures

| File | Covers |
| --- | --- |
| `simple.html` | an ordinary document; the baseline |
| `nested-inline.html` | `<p>Hello <strong>bold <em>and italic</em></strong> world</p>`, adjacent runs with no whitespace, an existing `<br>` |
| `entities.html` | `&amp;` `&nbsp;` `&lt;` `&#39;` `&quot;` `&#x2014;` `&eacute;` surviving an unrelated edit, and a typed `&` being re-encoded |
| `comments-doctype.html` | a long PUBLIC doctype, conditional comments, a downlevel-revealed `<![if !IE]>`, an empty comment, a comment containing `>` and `--`, comments outside `<html>` |
| `messy.html` | unclosed `<P>`, uppercase tags, single-quoted attributes, `>` inside an attribute value, spaces around `=`, unquoted values, bare `<` and `>` in running text, an implicit `<tbody>` |
| `scripty.html` | inline `<script>` full of HTML-looking string literals, `</div>` inside a string, `<style>` with markup in a comment, JSON in a `<script type>`, an inline event handler |
| `pre-template.html` | the newline `<pre>` eats, `<template>`, `<noscript>` as raw text, `<textarea>` with entities |
| `crlf.html` | CRLF line endings survive an edit (generated from `simple.html`) |
| `large.html` | ~1MB, 46k text nodes; generated by `node test/make-large.js`, not committed |

## What the editor suite does

`editor-test.html` **is** the document under test. It fetches its own source,
builds the offset map over itself, and runs real edit mode on it — which is
exactly what the extension does to a local file. The harness's own output is
inside an element marked `data-quick-edit-ui`, which the map excludes, so the
test scaffolding never becomes editable text.

Typing is simulated by dispatching `beforeinput`, performing the mutation the
browser would have performed, then dispatching `input` — the exact contract
`editor.js` is written against. Enter, paste and refused commands are not
simulated at all: those paths cancel the browser's default and do the work
themselves, so dispatching the event is the whole story.

The file that *would* be saved is inspected with `QuickEditEditor.preview()`,
which returns the spliced bytes without starting a download.

| Check | Claim |
| --- | --- |
| no edits | with edit mode on and nothing typed, `preview()` is byte-identical to the source |
| typing | the typed text reaches the file and **every byte outside that one range is unchanged** |
| escaping | typed `<`, `>` and `&` are encoded, never written raw, and parse back to what was typed |
| Enter | a `<br>` lands inside the edited region; the tags beside it do not move |
| refusals | bold, italic, indent, lists, links, horizontal rules, drops, and an unrecognised input type are all cancelled and change nothing |
| paste | markup on the clipboard is discarded and only plain text is inserted; newlines become `<br>` |
| undo/redo | text and entities return to the original bytes, across several regions, in order |
| leaving edit mode | islands holding unsaved edits are kept but disarmed, and re-arm on the way back in |
| end to end | the only elements gained are the `<br>`s that were deliberately inserted; no wrapper or `contenteditable` leaks into the file |

## In a real browser

Three things no headless suite can check: that Chrome will let the extension
read a `file://` URL, that the download happens, and that it feels right to use.
[MANUAL.md](MANUAL.md) is the step-by-step for those.

## Verifying byte-level preservation by hand

The automated suites assert it, but the whole product rests on this, so it is
worth doing once with your own eyes.

**A file you did not edit must save byte-identical.**

1. Open a fixture from a `file://` URL, e.g.
   `file:///path/to/quick-edit/test/fixtures/messy.html`
2. Click the Quick Edit icon and turn on edit mode.
3. Change **nothing**. Save.
4. Save it somewhere other than over the original, then compare:

```bash
cmp test/fixtures/messy.html ~/Downloads/messy.html && echo "IDENTICAL"
```

`cmp` prints nothing and exits 0 when the files match to the byte. If you would
rather see it spelled out:

```bash
diff <(xxd test/fixtures/messy.html) <(xxd ~/Downloads/messy.html)
```

Zero lines of output is the pass condition. Not "looks the same", not "diff
shows only whitespace" — zero.

**A file you did edit must differ only where you typed.**

Repeat with one word changed, then:

```bash
diff -u test/fixtures/nested-inline.html ~/Downloads/nested-inline.html
```

Every reported change should be a word you typed. Line counts, indentation,
attribute quoting, comments and the doctype should all be absent from the diff.
